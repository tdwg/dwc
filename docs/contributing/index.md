# Guidelines for contributing

## What can I do for Darwin Core?

Anything that makes Darwin Core more useful, conducted with respect and understanding. In particular, you can:

- learn more about Darwin Core and how to use it. Useful starting points include the [Darwin Core Quick Reference Guide](../terms/), the [Darwin Core conceptual model](../cm/), the [Darwin Core Data Package guide](../dp/), and the [Darwin Core Schemas](../schemas/)
- read the documentation with a critical eye. If something does not make sense or is unclear, the Darwin Core Maintenance Group wants to know about it
- ask questions about Darwin Core by opening an issue in the [Darwin Core Questions & Answers repository](https://github.com/tdwg/dwc-qa/issues) or by sending email to [tdwg-content@lists.tdwg.org](mailto:tdwg-content@lists.tdwg.org)
- help other users find answers by responding to questions or pointing them to relevant documentation
- share implementation experience, examples, and guidance through the [Darwin Core Questions & Answers repository](https://github.com/tdwg/dwc-qa)
- review and comment on open [Darwin Core issues](https://github.com/tdwg/dwc/issues), especially issues that are in public review
- contribute corrections or improvements to the Darwin Core website and supporting materials in this repository

## How can I propose a change to the Darwin Core standard?

Changes can be proposed at any time. Proposals are developed through the Darwin Core issue tracker and are considered for inclusion in a maintenance cycle once they are sufficiently mature.

For a change to be considered, it should address the three justifications required by the TDWG Vocabulary Maintenance Specification:

- **Demand** — there is demonstrated need for the change
- **Efficacy** — the proposed change addresses that need effectively
- **Stability** — the consequences for existing implementations and users have been considered

The requirements are described in Section 3.1, *Justifications for Change*, of the [TDWG Vocabulary Maintenance Specification](https://github.com/tdwg/vocab/blob/master/vms/maintenance-specification.md).

To initiate a change request, create a [new Darwin Core issue](https://github.com/tdwg/dwc/issues/new/choose) and use the most appropriate issue template. Fill it out as clearly, concisely, and completely as possible. If some information is not yet available, the Darwin Core Maintenance Group can help develop the proposal toward maturity.

- To propose a change to an existing Darwin Core term, use the [term change template](https://github.com/tdwg/dwc/issues/new?template=term-change-template.md).
- To propose a new Darwin Core term, use the [new term template](https://github.com/tdwg/dwc/issues/new?template=new-term-template.md).
- For other proposed changes to the standard, use the [issue chooser](https://github.com/tdwg/dwc/issues/new/choose) and select the most appropriate template.

If you cannot or do not wish to use GitHub, send the proposal to [tdwg-content@lists.tdwg.org](mailto:tdwg-content@lists.tdwg.org).

## What happens after a change is proposed?

The Darwin Core Maintenance Group works with proposers and other participants to clarify proposals, assess their implications, and determine whether they are ready for public review.

Darwin Core maintenance proceeds in recurring review cycles. Mature proposals are assigned to a review cycle, opened for public comment, evaluated for consensus, and, when appropriate, assembled into a release candidate for ratification by the TDWG Executive Committee.

The annual schedule and the maintainer checklist for this process are documented on the [Darwin Core Maintenance page](../maintenance/).

Not every issue results in a change to the standard. An issue may instead lead to clarification, improved documentation, a revised proposal, or a decision that no change is needed.

## Have a question about Darwin Core?

For questions about how to interpret or use Darwin Core, use the [Darwin Core Questions & Answers issue tracker](https://github.com/tdwg/dwc-qa/issues) or send email to [tdwg-content@lists.tdwg.org](mailto:tdwg-content@lists.tdwg.org).
